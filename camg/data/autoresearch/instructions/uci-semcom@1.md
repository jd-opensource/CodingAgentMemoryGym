## Public description

SECOM Yield Failure Prediction

Problem
Predict downstream yield failures in a semiconductor manufacturing process. Each unit is described by hundreds of sensor measurements collected at a test point. Your task is to train a model that outputs, for each test unit, the probability that it fails.

Data
- Train file: train.csv
  - Columns: id, 590 numeric sensor features (named 0..589), label
  - label: 0 = pass, 1 = fail
- Test file: test.csv
  - Columns: id, 590 numeric sensor features (named 0..589)
- Sample submission: sample_submission.csv
  - Columns: id, failure_probability

Notes
- The original collection includes a timestamp per unit. For this competition, the split is time-based (earliest 80% as train, latest 20% as test), but the timestamp is not included in train/test files to avoid calendar leakage.
- The dataset contains missing values and many features; some features can be constant or highly sparse. Robust preprocessing (imputation, scaling, feature selection/regularization) is important.
- The class distribution is highly imbalanced (failures are rare). Use techniques like class weights, imbalance-aware losses, or threshold calibration.

Evaluation
- Metric: ROC-AUC on the failure class.
  - Submissions must provide a probability for each test id (values in [0, 1]).
  - ROC-AUC is threshold-free and assesses how well your model ranks failing units ahead of passing units, which is appropriate under severe class imbalance.

Submission format
- A single CSV file with columns: id, failure_probability
- id must match the ids in test.csv exactly; one row per test id; no duplicates.

Suggested approach
- Data processing: handle missing values robustly; consider adding missingness indicators.
- Feature engineering: remove constant features; optionally filter features with near-complete missingness or apply dimensionality reduction.
- Model training: try linear models with regularization, tree-based ensembles, or kernels; ensure outputs are calibrated probabilities.
- Model evaluation: use cross-validation on the training set (e.g., time-aware splits); avoid leaking information from the test set.
