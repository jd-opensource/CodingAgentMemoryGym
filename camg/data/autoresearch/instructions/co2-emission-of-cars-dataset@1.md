## Public description

Title: Cross‑Domain Vehicle CO2 Emissions Prediction

Problem statement
Build a model to predict real‑world CO2 emissions (grams per kilometer) for vehicles using rich specifications and telematics‑style aggregates. The data combines two sources with different schemas: a large telematics/spec dataset and a small curated cars table. Your model should generalize across both sources.

Files provided
- train.csv: Training rows with features and the target column co2_g_km. Includes a row_id identifier.
- test.csv: Test rows with the same features as train.csv (without the target). Includes a row_id identifier matching the submission format.
- sample_submission.csv: Example submission with the required columns.

Target
- co2_g_km (numeric): CO2 emission in grams per kilometer.

Features
- Tabular mixture of:
  - Vehicle specs: engine_cc, vehicle_weight, make, fuel_type, model_year, cylinders, vehicle_age, annual_mileage_km, region.
  - Aggregated telemetry/context: ambient_temp_avg_1..40, altitude_avg_1..40, avg_speed_kmh_1..70, hard_brake_rate_1..70, exhaust_temp_1..60, engine_wear_index_1..50, and potentially policy/context features such as emission_limit_region_*.
- Identifier columns and any direct target surrogates are removed. All features in train/test align by name.

Evaluation
- Metric: Macro‑averaged Mean Absolute Error (MAE) across data sources.
  - During evaluation, MAE is computed separately on the subset of test rows originating from each source and then averaged (unweighted) to produce the final score. This ensures performance is balanced across domains and the larger source does not dominate the metric.
  - Units: grams per kilometer (lower is better).

Submission format
- A CSV with the following two columns and no header/column order changes:
  - row_id: Identifier matching test.csv
  - co2_g_km: Your predicted CO2 value (numeric, finite)

Notes and guidance
- The split ensures both sources are present in train and test for robust evaluation.
- Strong baselines include gradient boosted trees, regularized linear models, or neural nets with embedding layers for categoricals.
- Recommended practices:
  - Handle missing values carefully (imputation + missingness indicators).
  - Encode high‑cardinality categoricals (make, potentially region) thoughtfully.
  - Consider feature scaling/clipping for continuous features and summary statistics for sequential aggregates.
  - Avoid using any derived target surrogates; such columns are removed from the provided train/test files.
