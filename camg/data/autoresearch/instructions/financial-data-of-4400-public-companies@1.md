## Policy actions

You have one global budget of 30 ordinary actions. Every `shell_command`, `apply_patch`, and `submit` consumes one action, including rejected or failed actions. A compound shell command is one policy action, while every managed Python start is counted separately. Use only one action per response.

- `shell_command {"command":"...","workdir":".","timeout_ms":20000}`
- `apply_patch` followed by one `*** Begin Patch` / `*** End Patch` envelope
- `submit {}` grades `submission.csv` exactly once and always terminates

`TASK.md` and `data/` are read-only. Network, package installation, GPU access, and host paths are unavailable. The shell-action wall limit is 20 seconds and the managed-runtime aggregate limit inside one shell action is 15 seconds.

## Public description

Title: Next-Quarter Operating Cash Flow Forecasting

Background
Operating cash flow (CFO) measures cash generated by a company’s core operations and is central to liquidity, solvency, and valuation. Predicting near-term CFO from recent financial statements is useful for credit risk assessment, investment screening, and cash planning.

Problem statement
Given the last three chronological quarters of a company’s financial statements, predict its total cash from operating activities (CFO) in the next (fourth) quarter.

Data
Each sample represents one publicly listed company with four consecutive quarters available. For each company:
- Features: Only the first three quarters are used to construct features, drawing from the quarterly income statement, balance sheet, and cash flow statement. Optionally, the most recent annual statements strictly prior to the target quarter’s year are included as additional context features.
- Target: totalCashFromOperatingActivities for the fourth quarter (not included in feature columns).

Files
- train.csv: Feature matrix with a target column named target.
- test.csv: Feature matrix for which you should predict target.
- sample_submission.csv: An example submission file with the required columns.
- description.txt: This description file.

Important modeling notes
- No data from the target quarter is present in features, across any statement types; this prevents label leakage.
- The stock identifier is not included as a feature and should not be used for prediction. An id column uniquely identifies each row.
- Data contain missing values and heavy-tailed distributions. Robust preprocessing, feature engineering (ratios, margins, lags, deltas), and models (e.g., gradient boosting, robust losses) are encouraged.

Evaluation
- Primary metric: Symmetric Mean Absolute Percentage Error (SMAPE) on the target quarter’s CFO.
  SMAPE = mean over all test rows of [ 2 * |y_pred − y_true| / (|y_pred| + |y_true|) ]
  Notes: SMAPE is scale-aware and handles negative values gracefully. If both |y_pred| and |y_true| are zero, the term is defined as 0 to avoid division-by-zero.

Rules and expectations
- Use only the information present in the provided train.csv and test.csv. External data is not required.
- You are free to engineer features from provided columns (e.g., margins, leverage, liquidity, working-capital dynamics, trends and volatility). Ensure your pipeline avoids any leakage from the target quarter.
- Standard ML approaches for tabular forecasting are applicable: tree ensembles, linear/regularized models, or neural networks for tabular data.

Deliverable
- Submit a CSV with two columns: id and target, where target is your prediction for next-quarter CFO for each row in test.csv.

Summary
This competition challenges you to forecast a company’s next-quarter operating cash flow from its three preceding quarters of financial statements, optionally leveraging prior-year annual context. The task is economically meaningful, time-aware, and designed to reward robust modeling under heterogeneity, missingness, and heavy-tailed targets, evaluated via a fair and robust SMAPE metric.
