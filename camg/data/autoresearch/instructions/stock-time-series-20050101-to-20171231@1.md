# OpenMLE-fast task

Task ID: `stock-time-series-20050101-to-20171231@1`

Native metric: `StockReturnRankingMetrics` (higher is better).

Create `/workspace/submission.csv` with the same row count and required columns as `data/sample_submission.csv`. Training labels are in `data/train.csv`; test features are in `data/test.csv`. Evaluation runs across an isolated boundary.

## Policy actions

You have one global budget of 30 ordinary actions. Every `shell_command`, `apply_patch`, and `submit` consumes one action, including rejected or failed actions. A compound shell command is one policy action, while every managed Python start is counted separately. Use only one action per response.

- `shell_command {"command":"...","workdir":".","timeout_ms":20000}`
- `apply_patch` followed by one `*** Begin Patch` / `*** End Patch` envelope
- `submit {}` grades `submission.csv` exactly once and always terminates

`TASK.md` and `data/` are read-only. Network, package installation, GPU access, and host paths are unavailable. The shell-action wall limit is 20 seconds and the managed-runtime aggregate limit inside one shell action is 15 seconds.

## Public description

Title: Cross-Sectional Next-Day Return Ranking

Problem statement
- For each trading date t, predict a score for every stock present on that date that ranks the stocks by their next trading day log return r_{s,t+1} = ln(Close_{s,t+1}/Close_{s,t}). The objective is to produce accurate per-date cross-sectional rankings across all tickers.

Data description
- You are provided with daily OHLCV panel data for large-cap US stocks over 2006–2017.
- Final competition data files:
  - train.csv: Rows are (Date, Name, Open, High, Low, Close, Volume, NextDayLogReturn). Labels are provided only where the next trading day exists.
  - test.csv: Rows are (Date, Name, Open, High, Low, Close, Volume). Labels are withheld.
  - sample_submission.csv: A valid example submission with the required schema.
- Columns
  - Date: Trading date in YYYY-MM-DD.
  - Name: Stock identifier (ticker string).
  - Open, High, Low, Close: Daily prices in USD.
  - Volume: Shares traded.
  - NextDayLogReturn (train only): ln(Close_{t+1}/Close_{t}).

Train/test split
- Train: All rows with Date in 2006-01-03 through 2016-12-30 (inclusive) where the next trading day exists for that stock.
- Test: All rows with Date in 2017-01-03 through 2017-12-28 (inclusive) where the next trading day exists for that stock. Rows whose next trading day is missing are excluded to ensure well-defined labels for evaluation.
- The split is strictly by time to prevent leakage.

Task and expectations
- Build models that assign, for each date, comparable scores across stocks using only information available up to and including date t. Typical approaches include:
  - Data processing: Parsing dates, sorting by stock/date, handling missing values, and aligning by trading calendar.
  - Feature engineering: Rolling returns and volatility, moving averages, price gaps, ranges ((High−Low)/Open), RSI-like oscillators, volume features, cross-sectional z-scores per date, etc.
  - Model training: Supervised learning on the train.csv using NextDayLogReturn as the target. Any ML approach is acceptable (e.g., gradient boosting, linear models with regularization, sequence/panel models).
  - Model evaluation: Use the metric defined below. Ensure features are computed without look-ahead beyond date t.

Submission format
- CSV with columns: Date, Name, Pred
  - Date and Name must match exactly the rows in test.csv.
  - Pred is a numeric score; higher implies expecting a higher next-day log return. Scores can be on any monotonic scale.

Evaluation metric
- Spearman rank correlation averaged over dates:
  - For each test date t, compute Spearman correlation between submitted Pred scores and the true next-day log returns across all stocks present on t.
  - The final score is the mean of these per-date correlations.
  - Robustness rules: If a date group has fewer than 2 stocks or either vector is constant (all equal), its correlation contribution is defined as 0 to avoid undefined values.
- Rationale: Spearman focuses on ranking, aligning with portfolio selection goals and providing robustness to scale differences and heteroskedasticity in returns.

Notes
- Use only data up to and including date t to generate features for test rows.
- No external data is required. The panel provided is sufficient for ML-based forecasting.
- The provided sample_submission.csv demonstrates the required schema with deterministic random scores.
