## Public description

Human vs AI Text Classification Challenge

Problem statement
Build a model that, given a piece of text, predicts the probability that it was generated by AI (as opposed to written by a human). Your goal is to minimize binary log loss on a held-out test split.

Why this matters
As AI-generated text proliferates, reliably distinguishing it from human writing is important for moderation, provenance, academic integrity, and safety. This competition emphasizes both discrimination and probability calibration.

Files provided
- train.csv: Labeled training data with columns:
  - id: Unique identifier for each sample
  - text: The input text
  - label: Binary label where 1 = AI-generated, 0 = human-written
- test.csv: Unlabeled test data with columns:
  - id: Unique identifier
  - text: The input text
- sample_submission.csv: Example submission with columns:
  - id
  - proba_ai: Your predicted probability that the text is AI-generated (a float in [0, 1])

Data details and split protocol
- Size: 5,000 total samples; balanced: 2,500 AI-generated and 2,500 human-written.
- We perform a deterministic split: 4,000 rows for train and 1,000 rows for test.
- Duplicate/near-duplicate control: We detect duplicates via a normalized-text signature (lowercased text with collapsed whitespace) and keep all exact matches in the same split to prevent leakage.
- Balanced co-stratification: The split is stratified by label and co-stratified by simple style proxies to reduce trivial heuristics dominating one split. Specifically, we balance by:
  - Text length deciles
  - Presence of first-person pronouns (e.g., “I”, “my”, “we”)
  - Presence of topical tokens related to AI (e.g., “AI”, “artificial”, “intelligence”, “machine”)
- The dataset files are plain UTF-8 text; no additional assets are required.

Evaluation
- Metric: Binary log loss on the private test set using the probability for the positive class (AI-generated).
- Definition: For each sample i with true label y_i ∈ {0,1} and submitted probability p_i ∈ [0,1],
  LogLoss = - (1/N) * Σ [ y_i * log(p_i) + (1 - y_i) * log(1 - p_i) ]
- Numerical stability: During scoring, probabilities may be clipped to a small epsilon away from 0 and 1 to avoid log(0).

Submission format
- A single CSV file with columns:
  - id
  - proba_ai
- The id values must match those in test.csv exactly and appear exactly once. The proba_ai values must be finite floats in [0, 1].

Rules and guidance
- External data: Do not use external labeled human-vs-AI datasets. Using public, generic pretrained language models or embeddings is allowed as long as they are not trained on overlapping labeled data specific to this task/test.
- Fair use: Any provided artifacts (e.g., baseline notebooks/models) are for reference only; do not use them to infer private-test-specific behavior.
- Suggested approaches: Consider both classical and modern NLP methods, such as TF-IDF n-grams with linear models, character-level features, stylistic/linguistic features, pretrained transformers, and probability calibration (e.g., Platt scaling or temperature scaling) to optimize log loss.

Important notes
- Labels in both train and test cover both classes; you should expect balanced class distributions.
- The split is deterministic and leakage-controlled, so results should be reproducible across runs given the same pipeline.

Good luck and have fun building robust, well-calibrated detectors!
