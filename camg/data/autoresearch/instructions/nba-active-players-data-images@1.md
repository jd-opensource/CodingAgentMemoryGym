# OpenMLE-fast task

Task ID: `nba-active-players-data-images@1`

Native metric: `NBARoleRecognitionMetrics` (higher is better).

Create `/workspace/submission.csv` with the same row count and required columns as `data/sample_submission.csv`. Training labels are in `data/train.csv`; test features are in `data/test.csv`. Evaluation runs across an isolated boundary.

## Policy actions

You have one global budget of 30 ordinary actions. Every `shell_command`, `apply_patch`, and `submit` consumes one action, including rejected or failed actions. A compound shell command is one policy action, while every managed Python start is counted separately. Use only one action per response.

- `shell_command {"command":"...","workdir":".","timeout_ms":20000}`
- `apply_patch` followed by one `*** Begin Patch` / `*** End Patch` envelope
- `submit {}` grades `submission.csv` exactly once and always terminates

`TASK.md` and `data/` are read-only. Network, package installation, GPU access, and host paths are unavailable. The shell-action wall limit is 20 seconds and the managed-runtime aggregate limit inside one shell action is 15 seconds.

## Public description

NBA Role Recognition from Headshots + Bio (2022–23)

Problem statement
Build a model that predicts an NBA player’s primary on-court role — Guard, Forward, or Center — using both their headshot image and biographical data. Each test row corresponds to a unique player active in the 2022–23 season. Competitors are encouraged to explore multimodal learning that fuses visual and tabular information.

Data description
- Training data
  - train.csv: one row per training player with columns: playerid, image, fname, lname, height, weight, birthday, country, school, draft_year, draft_round, draft_number, label. The image filename corresponds to a PNG stored in the train_img/ folder.
  - train_img/: headshot images for training players. Filenames are anonymized numeric IDs and do not contain labels.
- Test data
  - test.csv: same columns as train.csv except without label. The image filename corresponds to a PNG stored in the test_img/ folder.
  - test_img/: headshot images for test players.
- Submission format
  - submission.csv must contain columns: playerid, Guard, Forward, Center. Values should be class probabilities that sum to 1 for each row.

Target label
- label is the player’s primary position derived from the position field by taking the first token before a hyphen (e.g., “Guard-Forward” becomes Guard). The three classes are Guard, Forward, Center.

Recommended feature engineering (optional)
- Images: standard vision preprocessing (resize, normalization) and augmentations. Face-cropping or alignment may help. Transfer learning (e.g., ImageNet-pretrained CNNs) is expected to be effective.
- Height/weight: convert height from feet-inches (e.g., 6-8) to inches or centimeters; use weight in pounds; consider BMI-like features.
- Birthday: compute age as of 2022-10-01 to avoid time leakage; optionally draft_age = draft_year − birth year.
- Country and school: treat as categorical features or text embeddings; include an explicit Unknown category when missing.
- Draft info: engineered features such as drafted_flag, draft_round (impute −1 for undrafted), draft_number (impute −1), and years_since_draft.
- Names: simple character/word n-grams can provide weak priors; using them is allowed but not required.

Evaluation
- Metric: macro-averaged F1 on hard predictions derived from submitted probabilities (argmax). This treats the three classes equally and counters class imbalance.
- Format validation: submissions must include exactly the test playerid values once each and numeric probabilities for each class. Probabilities will be normalized during scoring if they do not sum to 1 or contain small numerical issues.

Train/test split
- The official split is provided in the files above. It is stratified by class to preserve balance. All test labels occur at least once in the training set.

Rules and notes
- Do not infer labels from filenames or paths; filenames are anonymized numeric IDs.
- Do not add external data unless it is strictly pretrained backbones without using labels from the competition test set.
- Use of both modalities (image + tabular) is encouraged but not required; tabular-only and image-only approaches are valid baselines.

Files provided
- train.csv
- test.csv
- train_img/
- test_img/
- sample_submission.csv (example with random probabilities)

Good luck, and have fun building robust multimodal classifiers that understand the link between player anthropometrics, biography, and role!
