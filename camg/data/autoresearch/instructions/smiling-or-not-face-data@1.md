# OpenMLE-fast task

Task ID: `smiling-or-not-face-data@1`

Native metric: `SmilingOrNotMetrics` (higher is better).

Create `/workspace/submission.csv` with the same row count and required columns as `data/sample_submission.csv`. Training labels are in `data/train.csv`; test features are in `data/test.csv`. Evaluation runs across an isolated boundary.

## Policy actions

You have one global budget of 30 ordinary actions. Every `shell_command`, `apply_patch`, and `submit` consumes one action, including rejected or failed actions. A compound shell command is one policy action, while every managed Python start is counted separately. Use only one action per response.

- `shell_command {"command":"...","workdir":".","timeout_ms":20000}`
- `apply_patch` followed by one `*** Begin Patch` / `*** End Patch` envelope
- `submit {}` grades `submission.csv` exactly once and always terminates

`TASK.md` and `data/` are read-only. Network, package installation, GPU access, and host paths are unavailable. The shell-action wall limit is 20 seconds and the managed-runtime aggregate limit inside one shell action is 15 seconds.

Smiling or Not — Robust Face Expression Classification

Problem statement:
Given a face image, predict whether the person is smiling (positive class) or not (negative class). You will train on labeled face crops and predict the probability of the “smile” class for a hidden test set of faces. The dataset may also include additional unlabeled faces that you can optionally use in semi-supervised ways (without accessing test labels).

Data provided:
- train.csv: CSV with two columns [id,label]. id is the image filename in the train_images folder; label is 0 (non-smile) or 1 (smile).
- train_images/: Folder containing the training images referenced by train.csv. All files are 64×64 JPEGs.
- test.csv: CSV with one column [id]. id is the image filename in the test_images folder.
- test_images/: Folder containing the test images referenced by test.csv. All files are 64×64 JPEGs.
- sample_submission.csv: Example submission with the correct format. The target column contains example probabilities in [0,1].
- extra_unlabeled/ (optional): Optional folder of additional face images with no labels, for semi-supervised learning or representation learning if present. It may be empty.

Notes on preparation and integrity:
- All images have been validated to be JPEGs and renamed to neutral IDs to avoid label leakage.
- Train/test splits are deterministic and stratified by label with duplicate-image protection using MD5 hashes.
- The train and test sets both contain examples of each class.

Task expectations:
Participants are expected to apply sound machine learning practices, including but not limited to:
- Data processing: normalize/standardize pixels, robust image loading, and optional face-centric augmentations.
- Feature engineering: augmentation (flip/rotate/scale/brightness/contrast), regularization, and potentially transfer learning.
- Model training: CNNs (from scratch or pretrained), classical models on learned features, or semi/self-supervised approaches leveraging extra_unlabeled if available.
- Model evaluation: monitor validation locally (e.g., hold-out or CV within train), avoid overfitting with proper augmentation and early stopping.

Evaluation metric:
- Metric: ROC-AUC computed on the submitted probabilities for the “smile” class. Submit a CSV with two columns [id,target], where target ∈ [0,1] is the predicted probability that the image shows a smile.
- Rationale: ROC-AUC is threshold-independent, robust to class imbalance, and evaluates ranking quality precisely even when probabilities are imperfectly calibrated.

Submission format:
- A single CSV file with header: id,target
- id must exactly match the filenames listed in test.csv.
- target must be a finite numeric value in [0,1].

Final files for the competition:
- train.csv
- train_images/
- test.csv
- test_images/
- sample_submission.csv
- extra_unlabeled/ (optional)

Tips:
- Use strong augmentation to generalize beyond the relatively small labeled set.
- Try transfer learning with shallow fine-tuning suited to 64×64 inputs.
- Consider semi-supervised techniques (e.g., pseudo-labeling) with extra_unlabeled if available.
- Ensure your submission includes all test IDs exactly once and valid probability values.
